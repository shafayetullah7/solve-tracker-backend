# Phase 2.10 — Performance budgets
Proposed acceptance targets, not measured capacity. Reviewed DATABASE_ARCHITECTURE, COMPLETION_ARCHITECTURE, SECURITY_RECOVERY_ARCHITECTURE and backend package.json. Preserve pinned stack and existing coding regression coverage.
## Reference environment
Benchmark isolated production builds on Linux 2 vCPU/4 GiB total allocation for backend, frontend SSR and PostgreSQL, load generator separate; also test actual shared VPS with cgroup CPU/memory limits and competing workloads. Record CPU model, storage, versions, pool sizes, dataset, warm/cold state and network. Initial envelope backend 512 MiB RSS, SSR 384 MiB RSS, PostgreSQL container 1 GiB including cache; remaining capacity for OS/proxy/headroom. These are targets not guarantees; no hard V8 heap setting until measured, RSS includes native buffers. Start pool max 10 per backend process, reserve DB connections for migrations/maintenance, measure wait and tune. No Redis, broker or microservice.
## Workload and targets
Seed 100 accounts, 10 guides/account, 100 nodes/guide, 5 blocks/node, representative 2 KiB payloads, 10 assessments/guide, 10 questions/assessment, 5 attempts/assessment, realistic mixed progress. Separate stress guide 2000 nodes/10000 blocks, deep and wide trees, many attempts. Synthetic only. Open-loop authenticated mixed workload 50 requests/s for 15 min, 70% reads/25% ordinary writes/5% assessment operations, multiple accounts and hot-guide contention separately. Ramp 10/25/50/100/200 until saturation; report achieved throughput, p50/p95/p99, errors, CPU/RSS, pool wait, locks, event-loop delay, DB I/O. Target p95 server HTTP list/node <=150ms, ordinary mutation <=250ms, normal guide tree/progress <=300ms, stress guide <=750ms, 100-question submit <=500ms; p99 ordinary <=1s, unexpected errors <0.1%, no lost/duplicate writes. Exclude media transfer/import/export from ordinary latency; test separately, bounded queue and explicit overload. 60-minute soak at sustainable load, no sustained RSS growth after warmup, verify existing coding p95 regression <=10% under matched workload (repeat runs). No promise of 1000 rps.
## Bounds
Proposed per account 100 active+archived guides, 2000 active nodes/guide, depth 32, 10000 blocks/guide, 200 blocks/node, 64 KiB/block, 32 MiB total authored payload/guide, 256 MiB authored payload/account excluding media; retained deleted data counts against separate bounded total quota, cannot bypass by delete/restore. 64 KiB note, 100 questions/assessment, 8 KiB/answer, 100 assessments/guide, 10000 attempts/account initial soft warning then explicit quota rejection, never silent purge. Reconcile hierarchy limits with earlier spec; enforce aggregate quotas atomically, imports same constraints. Import source max 8 MiB initial, normalized representation <=32 MiB, max 2 previews/account, 1 concurrent import/account, 2 global initially; larger exports may stream, no promise that single JSON import roundtrips max-size guide until reconcile: require supported export/import size parity or explicit segmented bundle. Private media limits from media spec. Ordinary request <=256 KiB except bounded batch/draft/import/media routes; explicit route caps before parsing. Initial DB statement timeout 2s ordinary, 10s bulk, lock timeout 1s; transaction deadlines and proxy/client timeouts aligned, cancellation verified.
## Query and rendering
Batch guide metadata and required evidence; no N+1, no rich payload in tree/list/progress. Target <=8 SQL statements for normal guide progress including auth (measure and document exceptions), <=5 for list, query count independent of node count. Index owner/status/order, parent/position, scoped enrollment progress, compatible finalized attempts, normalized problem URL, media refs; inspect EXPLAIN ANALYZE BUFFERS on synthetic DB only, avoid redundant indexes and indiscriminate JSONB GIN. Bound overview work to paginated guide summaries; no full account tree scan on dashboard; if needed derived read model with explicit freshness and authoritative detail. No server cache for private content initially; client account-scoped bounded cache, invalidate known dependencies, clear on auth epoch change. No public CDN caching of private data. 
Frontend: lazy route/editor/math/diagram/highlighting modules, no editor in study bundle, tree branch expansion and accessible virtualization only after profiling, render selected step only, lazy images, cancel stale requests, bounded prefetch. Target incremental learning overview/study initial JS <=100 KiB gzip above existing shell, editor lazy chunk <=250 KiB gzip provisional; measure actual build, no dependency upgrade for target alone. Mobile reference 4x CPU throttle, 1.6 Mbps down/150ms RTT, LCP <=2.5s, CLS <=0.1, interaction latency <=200ms in representative scripted interactions (lab proxy not field INP), report cold/warm and media separately. Preserve keyboard/screen reader access and 200% zoom.
