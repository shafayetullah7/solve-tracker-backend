# Phase 2.4 — Content and editor architecture
Proposed contract; complements DATABASE_ARCHITECTURE, HIERARCHY_ARCHITECTURE and frontend BLOCK_EDITOR_DESIGN. No implementation or dependency selection.

## Canonical format
Each block has stable UUID, guide/node scope, position, kind, schema_version, payload, required and revision. Server Zod 4 strict discriminated union by kind, then version-specific strict schema. Separate create/update/read contracts; server-managed identity/order/revision excluded from payload. Unknown fields/types rejected on ordinary writes. Read adapters for supported old versions; deterministic pure migrations, never silently discard data. Unsupported imported blocks warn and preserve bounded inert source in explicit unsupported representation, cannot gate completion. No arbitrary HTML, CSS, JS, iframe or executable code. JSONB object check supplements validation.
R1 kinds: rich_text (paragraph/heading/list/quote/table/callout typed AST), code (language, source, caption), math (TeX source, display), diagram (restricted declarative nodes/edges or approved static format), image (alt/caption, relational attachment), resource (title, safe URL, description), video_link (safe URL, title), checklist (stable item UUID/text), practical (instructions, self-attestation), assessment_ref and problem_ref (canonical relational links, not duplicate payload IDs). Only trackable activities may be required. R2 audio/file, toggles, flashcards, assignment references. No future empty handlers.
Rich text AST version 1: document -> bounded block nodes; paragraphs/headings contain inline text with allowlisted marks (bold, italic, strike, inline code, safe link); lists contain list items with bounded paragraphs/nested lists; tables rectangular bounded rows/cells with header semantics; quotes/callouts contain supported blocks. No arbitrary attributes, raw HTML or style. Exact schema fixtures before implementation. Stable checklist item IDs; rich text selection positions not durable identities; highlights later use block revision and quote context.
Registry backend maps kind/version to validator, normalizer, migration, trackability and reference extraction; frontend maps generated discriminated contracts to editor, renderer and activity UI. Exhaustive compile-time checks and shared fixtures, not shared runtime package by default. Explicit unsupported renderer. Assessment keys and learner state never embedded in authored payload. Relational references updated transactionally with block writes; media policy pending.

## Rendering and editor
Separate read-only semantic renderer from editing adapter; render text as text, allowlisted URL schemes (https/http for external links; no javascript/data/file), safe external link attributes; no automatic remote fetch, video link fallback. Math renderer must disable trust/unsafe commands and bound expansion; diagrams bounded and no scripts/HTML labels; code highlighting never execute source. CSP and XSS tests. Image delivery authorized separately. Evaluate native Solid 2 compatibility, IME, selection, paste, accessibility, SSR, bundle size and license before selecting rich-text engine; canonical AST independent of vendor, adapters round-trip fixtures. No dependency upgrades without approval. Keyboard reorder, slash picker, undo/redo local commands, mobile layout; sanitize pasted HTML into AST, never store raw HTML.

## Save protocol
Per-block content revision for payload edits; node content_revision for block membership/order, guide structure_revision for tree changes. All writers use hierarchy lock order guide then node then block; no network/media calls inside transaction. Patch sends expected block revision and operation ID; server validates ownership, lifecycle, payload and references, atomically writes and increments revision, returns authoritative record. Structural batch atomic with expected node revision. No-op does not increment. Operation ID scoped to actor/resource/action, payload hash, bounded retention; exact persistence contract security milestone. Duplicate identical operation returns original result or explicit reconciliation, changed payload conflicts. Stale revision 409, no silent last-write-wins. Client debounce proposed 600ms, one in-flight save per block, coalesce latest draft, never overwrite newer local edits with old acknowledgment. Explicit save on blur/navigation when possible; do not rely on unload. Network failure retains draft, bounded retry only idempotent operations. Conflict presents server/local versions, copy or explicit reapply against latest revision. Local recovery account-scoped, bounded, clear on sign-out; sensitive offline persistence opt-in pending privacy review. Undo local unacknowledged changes or new revision-checked inverse command; never undo another session or assessment history.
Activity semantics: separate activity revision from cosmetic content revision; checklist item addition/removal or required-work change invalidates/reconciles according to completion spec; cosmetic edits do not erase evidence. Add explicit activity/requirement revision fields to logical schema during reconciliation.

## Portability and budgets
Markdown parse into canonical AST/blocks, fenced code headings not hierarchy; preview warnings, deterministic mapping and atomic import. JSON manifest version separate from block versions; remap identities and references, no personal state by default. Provisional limits per node 200 blocks, per block 64 KiB serialized payload, rich AST depth 16, checklist 100 items, table 50x20, code 32 KiB; attachments separate. Bound request total, parser time and math/diagram complexity in performance milestone. No unbounded bulk saves.

Real installed Solid 2 and Drizzle declarations and runtime baseline remain unverified. No application code, migrations or tests executed.
