# Phase 2.5 — Learning state and completion
Proposed refinement of LG-06/07/08/09 and DATABASE_ARCHITECTURE/CONTENT_EDITOR_ARCHITECTURE. Approved required-step denominator and best valid score preserved. No code or tests.

## Eligibility and modes
Active node is globally required iff its own required flag and every ancestor required flag are true. Optional branch excludes all descendants from guide denominator, but local subtree progress remains available relative to branch root (ignore root required flag for local view). Show effective optional status and warn on moves/toggles changing denominator. Deleted nodes excluded; archived guides readable with current progress but no learning writes. Structural mode counts zero own units, may have informational content but no required activities. Manual mode counts one own unit, including deliberately empty task; no required gates. Gated mode counts one own unit and requires at least one required trackable block; all gates AND, no additional manual confirmation. Reject inconsistent configurations atomically; adding first required block or removing last requires explicit mode transition. Parent own completion independent of children; optional work can be completed. Empty/structural-only denominator zero returns null percentage. Aggregate counts integers, percentage derived, display rounding never determines complete status. Guide complete iff total>0 and completed=total.

## Evidence
Manual completion stores timestamp and acknowledged node requirement revision; explicit reopen clears acknowledgment, repeated desired-state writes no-op. Gated completion derived from current evidence, cannot manually override; reopen individual checklist/practical activity or change requirements, never erase assessment attempts. Checklist nonempty, all current item IDs checked; preserve unchanged IDs on add/remove/reorder, new IDs incomplete; semantic replacement uses new ID or explicit reset, not automatic text inference. Practical self-attestation bound to activity revision. Problem reference resolves learner+normalized URL, solved status authoritative; missing/unsolved blocks gate, no judge verification. Assessment gate best finalized valid compatible revision score meets current threshold; pending/invalid excluded; exact compatibility/rounding next milestone. Missing or draft/archived assessment cannot satisfy gate; prevent newly required invalid links. Optional blocks never gate. Unknown content cannot gate. Expose reason codes per gate (incomplete, unresolved, pending_review, reassessment_required etc), distinguish unavailable/error from false.
## Revisions and edits
Add node requirement_revision and block activity_revision positive bigint; content revisions separate. Cosmetic edits, reorder, move preserve evidence; manual requirement changes explicitly invalidate acknowledgment (author chooses reset when meaning changes, mode changes always reset). Required flag changes denominator, not evidence. Checklist reconcile IDs transactionally; activity revision increments for semantic changes, carry surviving valid state explicitly. Practical instructions semantic change resets attestation; problem URL changes resolve new evidence; assessment compatibility governed by revision policy. Never delete history on edits. Deletion/restore follows hierarchy spec and recomputes current eligibility. Return affected counts and explain change reasons. No automatic subtree mark-all-complete in R1.
## Reads and writes
Use authoritative derived completion, not stored boolean/counter. Pure evaluator takes typed evidence; batched scoped queries or set-based SQL, no per-node query. Single consistent snapshot for tree/counts (one statement or read-only repeatable-read transaction); aggregate bottom-up O(n) from bounded metadata. Avoid loading rich content for progress; query only trackable fields. Manual/checklist/practical writes use desired state, expected requirement/activity revision and operation ID; lock guide then relevant rows, validate active enrollment and current IDs, upsert state, append explicit activity event only for actual transition in same transaction. Assessment/problem writes remain owned by their domains; no cross-domain fan-out writes. Current progress recomputed on read and frontend invalidated after known mutations. Historical events record explicit actions, not guaranteed historical derived completion snapshots; do not fabricate historical completion trend or combined streak. Future analytics snapshots require separate design. Resume updated on explicit study navigation, not prefetch; last activity distinct from completion. Self-reported mastery nullable five labels, no effect on gates, recommended R1 enhancement not mandatory per LG-08.
