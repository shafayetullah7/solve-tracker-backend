# Phase 2.12 — Implementation plan and reconciliation
Specification complete, not runtime validated. This document supersedes conflicting proposed defaults in earlier learning specs; six approved A0 decisions and LG/NFR MUST requirements remain binding. No source changes or tests.
## Resolved defaults
- Active nodes 2000/guide (supersedes 5000), depth 32, siblings 500, blocks 10000/guide and 200/node; 100 guides/account, 32 MiB authored payload/guide and 256 MiB/account, retained records count toward bounded quotas. All provisional pending benchmark. Quotas apply to import/copy/restore as well.
- Optional ancestor excludes descendants globally, local subtree counts relative to root. Structural zero own units, manual one, gated one with AND of required activities; empty denominator null. Archived guide read/export only, no learning writes; restore before editing. Current linked problem evidence may change archived displayed progress; label current, not frozen.
- Revisions positive bigint decimal strings; add guide metadata revision, node requirement revision, block activity revision, node deletion batch and deleted_at, active-only sibling uniqueness, explicit retained quota. Add owner-scoped operation receipts and import staging; activity events scoped to enrollment and guide via composite FK. Review exact FK actions and purge ordering in each slice. Owner enrollment created atomically; no public access.
- Assessment mutable draft separate from immutable revisions, stable logical question IDs, compatibility identity, deadline, terminal reason, invalidation and review metadata; one active attempt partial unique index. Exact integer scoring/pass comparison, bounded decimal numerical tolerance, short answer exact normalized match or explicitly labeled self-review. GET never finalizes expiry; explicit expiry POST/submit or bounded worker. Preserve history and best compatible valid score.
- Account lifecycle barrier before operation reservation then guide/node/domain/media locks; sorted same-level IDs; verify no inverse acquisition. Seven-day receipts, 30-day recoverable guide/subtree deletion, 24h media grace proposed. No silent history purge.
- R1 portable authored JSON and Markdown plus private image bundle for lossless supported cross-account authored export/import. JSON manifest alone explicitly excludes bytes; bundle uses versioned manifest, local asset IDs, checksums, bounded ZIP extraction, no arbitrary remote fetch. R1 must support roundtrip at allowed guide size: 8 MiB Markdown convenience limit, structured JSON/manifest cap initially 64 MiB with normalized authored quota 32 MiB; enforce separate metadata/assessment size limits and verify maximum export fits, otherwise segmented supported format before release. Bundle private image bytes bounded by 250 MiB account quota, stream/stage with disk limits, validate all before atomic guide visibility, durable media intents and cleanup on failure. No provider calls inside DB transaction. Exact archive library and storage/timeout budgets require spike; fail release gate if parity or privacy not proven. Personal records export separate, not imported as authored guide.
- Private media proxy subject to actual Cloudinary capability test; never fallback public. Existing public slots preserved. Theme toggle ships only after all existing and new screens verified. No speculative R2 tables, Redis or broker.

## Migration and commit discipline
Only feature/learning-guides in both repositories; never main. Inspect existing schema and pinned Drizzle declarations, generate timestamped SQL/snapshot with existing Kit, review constraints/indexes/backfill and registry; no db:push, no hand-edit applied migrations, no production migration. Additive migrations by slice; deploy schema before code using it, feature flag off, old code compatible where feasible; rollback application/flag first, preserve data, forward fix or tested restore for destructive failure. Run migrations on empty and existing synthetic DB, verify repeatability and rollback of failed transaction. No hand-edited generated API types; backend api:export/check then frontend api:generate/check against matching refs. Each slice commits implementation, tests, contracts and docs; report exact commands/results and unresolved failures. Do not claim verified from static inspection. No implementation before baseline gate; if execution environment unavailable, explicitly request local/connected execution rather than fabricate results.
