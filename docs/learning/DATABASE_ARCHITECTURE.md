# Phase 2.2 — Database architecture
Status: proposed logical schema; no migration or runtime verification. Read DRIZZLE_CONVENTIONS.md, existing users/problems/media tables and LEARNING_REQUIREMENTS.md. UUID identities follow existing user/problem/media conventions; timestamps timestamptz, snake_case SQL, camelCase TS, explicit updated_at writes. Drizzle 1.0.0-rc.5 schema barrels and v2 registry mandatory.

## Release 1 tables
Notation: all IDs UUID, PK id unless composite stated; timestamps created_at/updated_at on mutable entities, created_at on immutable events. NOT NULL unless marked nullable. Revisions bigint positive (API decimal string or bounded safe integer to be decided). All text/payload lengths bounded by later budgets.
- learning_guides: id, owner_id FK users, title text, description text, archived_at nullable, deleted_at nullable, structure_revision bigint, timestamps. unique(id,owner_id); owner/status/updated_at/id index. Private only; no public visibility API.
- learning_nodes: id, guide_id FK guide, parent_id nullable, title text, position integer >=0, required boolean, completion_mode PG enum `learning_node_completion_mode` (structural/manual/gated; API create/patch/import accept structural/manual only until gated UX), content_revision bigint, timestamps. unique(guide_id,id); composite FK (guide_id,parent_id) -> nodes(guide_id,id); check parent_id != id. Unique sibling positions using separate partial unique indexes for root (guide_id,position) and nonroot (guide_id,parent_id,position). Transactional reorder strategy next milestone; no direct cross-guide moves.
- learning_blocks: id, guide_id, node_id, position integer >=0, type PG enum `learning_block_type` (text/code/checklist/link), schema_version integer >0, payload jsonb object, activity_revision bigint, timestamps. composite FK (guide_id,node_id), unique(node_id,position). No grading keys or private learner state in payload.
- learning_import_previews: source_kind PG enum `learning_import_source_kind` (markdown/json/bundle; preview/commit API uses markdown/json only; bundle reserved).
- learning_enrollments: id, guide_id, learner_id FK users, resume_node_id nullable, last_activity_at nullable, timestamps. unique(guide_id,learner_id), unique(guide_id,id); composite FK resume node scoped to guide; clear resume before deleting referenced node. R1 service only permits owner enrollment, created atomically with guide. Future publishing requires separate access model, not enabled by schema.
- learning_node_progress: guide_id, enrollment_id, node_id, manual_completed_at nullable, acknowledged_requirement_revision nullable, mastery nullable bounded enum, timestamps; PK(enrollment_id,node_id); composite FKs guide/enrollment and guide/node. Current derived completion not stored as truth.
- learning_block_progress: guide_id,enrollment_id,node_id,block_id, activity_revision bigint, state jsonb object, timestamps; PK(enrollment_id,block_id); composite FKs guide/enrollment and guide/node/block. State typed per trackable block, no generic EAV.
- learning_notes: id, guide_id,enrollment_id,node_id, body jsonb validated document, schema_version, revision, timestamps; composite FKs guide/enrollment and guide/node; unique(enrollment_id,node_id) for R1 single contextual note.
- learning_problem_links: block_id PK, guide_id, normalized_url text, display_url text; composite FK guide/block. Resolve via existing problems(user_id,normalized_url) unique index, no private problem ID in portable content; deleted problem leaves reference unresolved. Link block payload does not duplicate canonical URL.
- learning_assessments: id, guide_id, title, active_revision_id nullable (draft), archived_at nullable, timestamps; unique(guide_id,id). Active revision composite FK added after revision table; same-assessment invariant.
- learning_assessment_revisions: id, guide_id, assessment_id, revision_number integer >0, passing_basis_points integer 0..10000, grading_policy_version, feedback_policy, created_at; unique(assessment_id,revision_number), unique(guide_id,assessment_id,id); composite FK guide/assessment. Published revisions immutable.
- learning_questions: id, revision_id FK revision, position integer >=0, kind, schema_version, prompt jsonb, grading_config jsonb, points integer >0, explanation nullable; unique(revision_id,position), unique(revision_id,id). Immutable with published revision; grading config excluded from learner response.
- learning_assessment_links: block_id PK, guide_id, assessment_id; composite FKs guide/block and guide/assessment. Block required flag is canonical gate.
- learning_attempts: id, guide_id,enrollment_id,assessment_id,revision_id,status, started_at, submitted_at nullable, finalized_at nullable, earned_points nullable, possible_points nullable, score_basis_points nullable, revision bigint, timestamps; composite FKs guide/enrollment and guide/assessment/revision; unique(id,revision_id); index(enrollment_id,assessment_id,revision_id,status,score_basis_points), index(enrollment_id,started_at,id). State checks and exact grading representation finalized in assessment spec; pending review excluded from best score.
- learning_answers: attempt_id, revision_id, question_id, response jsonb, awarded_points nullable, review_state, timestamps; PK(attempt_id,question_id); composite FKs attempt/revision and revision/question prevent cross-revision answers. Final answers immutable except explicit audited review workflow.
- learning_activity_events: id, guide_id,enrollment_id, kind, subject_id nullable, occurred_at, metadata jsonb typed and minimal; index(enrollment_id,occurred_at,id). Historical activity, not event sourcing; atomic with meaningful state transitions. No sensitive answer/note bodies. Idempotency identity policy later.

## Integrity and lifecycle
All nested operations scope by authenticated owner/learner and guide; composite FKs prevent cross-guide references but do not replace authorization. Root null uniqueness explicitly handled. Node cycle/depth checks require serialized structural transaction, not just FK. Archive readable/exportable, excluded from active recommendations; propose no content mutations until restored. Guide soft delete hides entire aggregate; purge after retention window (TBD) with explicit account deletion workflow. Node/block deletion must preserve historical attempts and activity: remove links and current progress only, assessment identity/revisions remain archived if referenced; contextual notes recovery policy required before hard delete. Avoid cascade from block to assessment/attempt. Account purge explicitly removes personal history and external media, with retry/reconciliation; exact FK actions and purge ordering reviewed before migration. No blanket cascade on historical entities. Resume fallback and subtree recovery next milestone.
## Media
Existing media usage_count 0..2 and public delivery are incompatible with arbitrary private attachments. Do not implement learning media FK or change slot check until dedicated privacy/reference migration spec. Proposed explicit learning attachment join, owner-scoped references, private delivery, staged upload and cleanup. Existing avatar/gallery regression required.
## R2 extension map (not migrations)
Question bank items + immutable revisions; flashcard decks/cards + learner scheduling state + review events; knowledge notes/bookmarks/links; project/assignment revisions + evidence/submissions/rubric; goals + target revisions; planned occurrences + study sessions. Reuse stable content IDs and enrollment where appropriate; standalone items allowed. No speculative tables now.
