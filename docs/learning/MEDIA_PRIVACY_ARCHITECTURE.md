# Phase 2.8 — Media privacy and lifecycle
Proposed amendment to MEDIA_CONVENTIONS.md, not implementation. Existing usage_count 0..2 represents gallery/avatar slots, and media-delivery.ts constructs public upload URLs. Neither is suitable for private learning. Keep existing pipeline and media identity; never treat an unguessable public URL as access control.
## Storage and reference model
Add immutable delivery classification legacy_public vs learning_private, provider delivery type and lifecycle state to media. Preserve existing public avatar/gallery behavior and 0..2 usage_count as legacy slot counter only; private assets require count=0, cannot attach to avatar/gallery. Explicit learning_block_media join (guide_id,node_id,block_id,media_id,owner_id,slot), composite scoped FKs to block/guide owner and media owner, unique block/slot; index media_id. No generic polymorphic FK or duplicated payload media IDs. R1 images only; R2 evidence/audio/documents use dedicated reference tables when implemented. Private library lists owned ready referenced assets separately; staged uploads accessible only via upload receipt/editor. Reuse private asset across owned guides, no duplicate bytes; copying legacy public image into private storage requires explicit user action and new asset identity; cannot retract previously public bytes. No public/private toggle. Existing gallery/profile queries and link guards explicitly exclude private class. Existing rows backfilled legacy_public; no bulk provider migration.
## Delivery
Verify Cloudinary account supports authenticated assets and restricted transformations before enabling private upload. Prefer authenticated backend streaming proxy for R1 strict per-request authorization; upstream authenticated URL generated server-side, never exposed to browser, fixed provider origin, no arbitrary URL fetch, no redirect to public CDN, bounded streaming/concurrency/timeouts, abort on disconnect. GET /media/:id/content checks session, owner, ready state and active reference or valid staged receipt; deleted-only references inaccessible except explicit authorized recovery workflow. Private no-store, nosniff, safe MIME, no-referrer, same-origin; image derivatives equally protected. No SVG/HTML active content. Signed short-lived bearer delivery alternative only after explicit privacy/cost review; signature alone does not guarantee expiration, test provider behavior. Cannot revoke already downloaded bytes. Test anonymous original and transformed URLs, expired credentials, cross-owner, archive/delete, browser cache and logs; fail closed if provider capability unavailable.
## Upload and lifecycle
Extend authenticated multipart /media with explicit private purpose (verify parser/guard/transport compatibility), reserve owner quota and durable upload intent with unique provider ID before network call. States reserved/uploading/ready/deleting/deleted or failed; upload outside DB transaction; validate provider metadata and finalize row transactionally. Reconcile ambiguous provider result by known ID, never blind duplicate upload. Validate magic bytes and decoded image dimensions, allow JPEG/PNG/WebP only initially, reject animation and SVG, strip metadata via verified re-encoding or provider processing; bound decoded pixels, bytes, time and concurrent uploads. No arbitrary remote URL ingestion. Staged ready asset has lease, attach only on successful block save; lock guide then node/block then sorted media IDs, verify owner/class/state, write references atomically. Deleting recoverable subtree retains references until purge; restore retains IDs. Removing last reference sets orphaned_at at detach, not created_at; attach clears it. Cleanup transaction locks media, checks all references/legacy slots and lease, marks deleting; no new attachments once claimed. Provider destroy outside transaction with durable retry state; not-found success; finalize tombstone/delete row only after confirmed destroy. Bounded worker within existing deployment, DB claim SKIP LOCKED, backoff, safe metrics, no Redis required. Account erasure must retain provider deletion jobs independent of cascading user rows until confirmed; design with auth lifecycle. Audit existing cleanup before enabling private rows; legacy cleanup must exclude private assets.
## Proposed budgets and rollout
Initial private images max 5 MiB encoded, 20 megapixels decoded, 2 concurrent uploads/user, 250 MiB/user private storage, 24h staged/orphan grace; 30d recoverable guide/subtree retention proposed, retained bytes count against quota. Reserve quota transactionally including pending uploads; release only on confirmed deletion. All limits provisional, benchmark and verify Cloudinary plan/egress. Prefer bounded image variants, avoid repeated transformations, measure proxy bandwidth and memory; no arbitrary provider URLs in DB. Export R1 JSON references manifest with explicit missing-media warnings, no claim of lossless cross-account media portability; R2 ZIP bundle or earlier if required by LG portability acceptance, resolve before release. Never export provider credentials or private signed URLs.
Migration sequence: inspect actual media schema/cleanup/profile/gallery/auth; additive classification and lifecycle fields, backfill, legacy regression; private reference constraints; upload/delivery capability tests; cleanup race tests; enable feature only after privacy verification. Tests: legacy slot transitions, public/private mixing rejected, cross-owner FK and API, upload interruption and orphan provider reconciliation, quota races, concurrent attach/cleanup, recoverable deletion, purge retries, account deletion, malformed/polyglot/oversized images, transformed URL access, no secret logs, proxy disconnect. No provider configuration, source code, migrations or tests changed. Final schema and MEDIA_CONVENTIONS amendment required before implementation.
