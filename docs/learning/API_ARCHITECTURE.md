# Phase 2.7 — API architecture
Proposed R1 contract inventory, not implemented OpenAPI. Follow BACKEND_CONVENTIONS.md and frontend API_CLIENT.md; existing routes unchanged. Prefix /learning; browser transport adds /api. UUID path validation, strict Zod body/query/path schemas, native Nest decorators, explicit response mapping, UTC ISO timestamps, camelCase. Revision tokens positive decimal strings (bounded PostgreSQL bigint), no JS number conversion. AuthSecurityGuard and AccessGuard on all routes; owner derived from session, cross-owner resource 404. No public endpoints.
## Routes
Relative to /learning; G=/guides/:guideId, N=G/nodes/:nodeId, A=G/assessments/:assessmentId, T=A/attempts/:attemptId. GET /guides paginated q/status/sort/order; POST /guides create owner enrollment atomically; GET/PATCH/DELETE G metadata/archive/recoverable delete. POST G/restorations restore deleted guide, POST G/copies duplicate authored content. GET G/tree bounded metadata with structureRevision; GET G/nodes paginated children/search (parentId or root filter, ancestor paths for search); POST G/nodes create with parentId/beforeNodeId/expectedStructureRevision; GET/PATCH/DELETE N read/update/delete subtree; PATCH N/placement move with parentId/beforeNodeId/expectedStructureRevision; POST N/copies copy to explicit destination guide; GET G/deletion-batches and POST G/deletion-batches/:batchId/restorations. Structural mutation responses include authoritative revision and changed metadata or explicit refetch requirement; DELETE 204 requires refetch, expected revision and operation ID in documented headers, not DELETE body. Metadata edits use separate guide metadata revision (schema amendment).
GET N/blocks bounded ordered list; POST N/blocks create; PATCH/DELETE N/blocks/:blockId edit/delete; PATCH N/block-order atomic ordered ID list with expectedNodeRevision; PATCH N/requirements atomic mode/required activity changes, expected relevant revisions. Required gate changes cannot be split into invalid intermediate states. GET/PATCH N/note single contextual note (PATCH upsert with explicit absent revision null); GET G/progress aggregate counts and optional subtree scope; GET N/progress gate reasons and own state; PATCH N/progress manual completion/mastery desired state; PATCH N/blocks/:blockId/progress typed checklist/practical desired state; PATCH G/resume explicit node navigation. Problem and assessment links authored through typed block mutations, not competing status endpoints.
GET/POST G/assessments list/create; GET/PATCH A metadata/archive; GET/PATCH A/draft bounded full draft with expected revision; POST A/revisions publish draft atomically; GET A/revisions paginated author history; GET A/revisions/:revisionId author snapshot. GET/POST A/attempts list/start-or-resume (201 new, 200 existing); GET T learner-safe attempt; PATCH T/answers bounded answer/flag batch; POST T/submissions final submit; PATCH T/status abandon only; GET/PATCH T/review self-review; GET T/result finalized or pending summary; POST T/invalidations audited explicit invalidation. Expiry processing on access must not be triggered by prefetch: use explicit POST T/expiry-finalizations or submit; GET reports effective expired status without mutation. This refines previous lazy-finalization proposal. Author and learner DTOs distinct; no grading config in active attempt. 
POST /imports preview bounded Markdown/JSON, POST /imports/:importId/commits atomic validated preview commit; GET G/export format markdown/json with explicit personal records option, safe attachment response or bounded JSON/text transport; no remote fetch. Preview identity bound to owner, source hash, expiry; exact storage/quotas later. GET /overview independent learning summary, existing coding progress unchanged. R2 routes deferred.
## Contracts
Single resources direct; paginated {items,meta:{page,pageSize,total}}, one-based page default25 max100, stable ID tie-breaker, filtered total. Bounded tree/block collections explicitly nonpaginated with revision metadata. 201 creation, 200 reads/updates/actions returning data, 204 deletion; 400 validation/invariant, 404 absent/inaccessible, 409 stale revision/lifecycle/idempotency conflict, 413 payload, 429 rate limit, existing auth codes unchanged. Proposed machine codes LEARNING_REVISION_CONFLICT, LEARNING_INVALID_PLACEMENT, LEARNING_REQUIREMENT_CONFLICT, LEARNING_ATTEMPT_STATE_CONFLICT, LEARNING_OPERATION_CONFLICT, LEARNING_IMPORT_EXPIRED; integrate existing error envelope, inspect actual exception mapping before implementation. Safe details only (current revision, field/reason), no foreign IDs or answer keys. Expired submit returns authoritative terminal result and terminalReason, not generic error. Progress counts {completedRequiredSteps,totalRequiredSteps,percentage:null|number,isComplete}; null for zero denominator; gate reasons typed, unavailable distinct from incomplete. Scores integer earned/possible/basisPoints, pending final score null, historical vs current eligibility separate.
Mutations carry operationId UUID and expected relevant revision; DELETE headers proposed X-Operation-Id and X-Expected-Revision require transport support/tests. Idempotency lookup after auth and before stale revision check, scope actor/resource/action, canonical payload hash; replay same operation returns original safe response or explicit reconciliation, conflicting reuse 409. Exact retention/storage in security milestone. No generic retry; existing one-time AUTH_REFRESH_REQUIRED recovery only before side effects; ambiguous network failures reconcile or explicitly retry same operation ID. Auth epoch and cancellation preserved.
